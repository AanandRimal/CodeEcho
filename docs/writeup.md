# DevTrust: finding and flagging duplicated code, and whether AI agents add more of it

Aanand Rimal. Built with AI assistance (Claude Code); see "Who made what" in the README. Every number below comes from `results/*.json`.

**Problem.** Developers, and AI coding assistants, often reimplement a utility that already exists in the repository because text search cannot find it under a different name. DevTrust (1) finds an existing function from a plain-language description, (2) flags newly added functions that resemble existing code, and (3) measures whether AI-agent pull requests do this more than human ones. None of the components is new; the contribution is a reproducible comparison on real repositories plus a usable CLI and MCP tool.

**RQ1: search.** 51 answerable queries over three Python repositories (instructor, fastmcp, crewAI), with relevance judged on candidates pooled from all systems, blind to which system found them. The code-specific embedder CodeRankEmbed was best (MRR 0.72, Recall@10 0.91), bge-small second (0.60, 0.71), BM25 well behind (0.28, 0.41). Identifier splitting helped BM25 (MRR 0.28 vs 0.20). Rank fusion (0.53) and cross-encoder reranking (0.39, about 20 times slower) scored below CodeRankEmbed alone. The explanations for those two are untested.

**RQ2: review.** Positives are Type 1-3 mutations of 60 real functions plus 25 hand-written Type-4 pairs; negatives are unrelated functions and hand-written look-alikes. Thresholds were chosen on a dev split and the test split was read once. At F1-optimal thresholds, adding an AST-based structural check did not reduce false positives compared with embedding-only (test false-positive rates 0.37 vs 0.34, within noise). At a stricter default the false-positive rate fell to 0.12, but Type-4 recall went to 0 and Type-3 recall to 0.83. All methods flag one-edit variants and most sibling functions. jscpd was precise but found few renamed or modified copies.

**RQ3: AI agents in the wild.** 763 merged pull requests: agent PRs from the AIDev dataset against a seeded sample of human PRs from the GitHub API, same repositories and period, counting only functions a PR adds. Of 108 human PRs and 89 agent PRs (Claude Code, Devin, Codex) with new functions, 35% of human PRs had a flagged function against 19% of pooled agent PRs. Part of that gap is PR size, since agent PRs add fewer functions. Per added function, Claude Code's rate was 0.185 against 0.113 for humans, not significant (p = 0.12). Devin's rate was significantly lower (0 of 57 functions). Codex had 10 eligible PRs, too few to conclude. Copilot, Cursor and Jules were too small to analyse. A manual audit of 40 flags found 16 real duplicates, 15 refactors the PR itself moved or edited, and 9 similar-but-different functions (precision 0.40). Excluding flags whose match the same PR removed, Claude Code (0.073) and humans (0.075) are about equal; this analysis was added after reading the audit, so it is exploratory.

**Honest summary.** There is no evidence on these repositories that agents duplicate more than humans. The detector is useful for finding candidates but is not precise enough to act on without a person checking.

**Limitations.** Queries, labels, the Type-4 pairs and the audit judgments were produced by AI and not validated by a human; the audit was not blind. Three repositories and small samples; agents are partly confounded with repository; humans may use unlabelled AI; detector thresholds come from synthetic data. A CosQA comparison and a human label check were dropped, and the MCP server has only a 16-run demo (reuse in 4 of 8 runs with the tool, 0 of 8 without), not an evaluation.
